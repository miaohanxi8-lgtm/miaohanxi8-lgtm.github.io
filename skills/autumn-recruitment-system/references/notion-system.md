## 使用原则

1. 每次写入前 fetch 对应数据源，使用最新字段和选项；fetch schema 不替代行数据读取。
2. 日常行数据先用上述 view mode 读取：page_size=100，并持续传入 next_cursor，直到 has_more=false。只有完成全部分页后，快照才可用于“记录不存在”的判断。
3. 把完整快照映射为 [脚本与数据契约](script-contracts.md) 的记录结构，使用 `scripts/recruitment_rules.py match` 按邮件 ID+发件人、UID+发件人、岗位编号/入口+域名等证据严格匹配。只有 `unique_match` 才 fetch 页面 URL 复核并更新；`ambiguous` 不得自动写入。
4. 同一次运行只加载一次所需数据库快照；创建或更新后立即同步修改内存快照，后续邮件不得重新查询同一数据库。
5. SQL mode 仅作备用：只有视图缺失、字段不足或缓存外历史记录无法判定时，才把本轮全部候选合并为每个受影响数据库最多一次参数化查询。严禁按邮件、岗位或任务逐条 SQL 查询。
6. SQL 额度耗尽时不重试，也不默认要求升级套餐。若完整视图快照已取得，继续执行；只有 view mode 也失败或分页不完整时，才停止写入且不提交 UID。
7. 关联字段使用页面 URL；正文中的岗位、任务、真实面试、模拟面试和能力节点均提供可点击链接。
8. 岗位库已移除匹配分、优先级、投递策略；不得重新创建或引用。
9. 岗位邮件字段包括最近邮件ID、最近邮件主题、最近邮件时间、最近邮件发件人、最近发件域名和最新进度日期。
10. 面试库使用场次类型、关联真实场次、关联模拟场次、关联任务、邀请邮件发件人；不再使用是否已创建任务。
11. 任务库当前行动字段的精确名称是“下一步做什么？”。写入笔试、测评、AI 测评或真人面试链路任务时，使用 Markdown 可点击链接，并优先把一键进入的入口放在开头；不能只把链接留在页面正文。
12. “下一步做什么？”应是一张简短执行卡：具体动作、首选入口、截止或开始时间，以及邮件明确提供且执行需要的平台、预计时长、剩余次数、会议号/访问码、地点、联系人、材料或设备要求。没有的信息不猜；邮箱授权码、账号密码、验证码等敏感凭据不得写入。

## 晚间自动化：复盘与明日早报

推荐每天 23:00 运行日常自动化：先读取当天日记和情绪打卡，并在当天日记页补充或更新“秋招每日复盘”区块，再生成目标日期为明天的早报。每日复盘写入复盘中心的日记数据库；早报写入早报数据库。两者不合并成同一页。

晚间生成的早报日期表示计划执行日期，不表示生成日期。例如 2026-09-02 23:00 自动化生成 `秋招邮件早报｜2026-09-03`，并在其中安排 2026-09-03 的“今日行动”。若用户白天手动要求当天计划，则仍生成当天日期的早报。

## 每日早报：行动与增量

每日读取上一条状态为“已生成”的早报、活跃岗位、今日与未来 7 天任务、真实/模拟面试、未确认项和能力图谱，按以下四段输出：

- 今日行动：一份 6–8 小时净工作量的有序计划，覆盖固定事项、每日模拟、最近笔面试准备、能力补缺、流程维护和日终收尾。
- 最新变化：上一份已生成早报之后发生、且未在行动区出现的变化。
- 未来 7 天：从明天起的关键节点。
- 待补全与需确认：会影响执行或去重的信息缺口。

同一事实只出现一次。今日行动顶部写计划总时长，每个时间块写优先级、预计用时、动作、完成标准和链接；固定日程计入总量，不虚构具体开始时间。每日能力提醒只选能力图谱中有证据的 1 个主缺口，必要时最多 2 个，并嵌入对应工作块。建议任务默认只读，不自动批量创建学习任务；但用户已明确授权每天创建或复用恰好一条模拟面试待办，不得提前批量生成。

晚间自动化生成明日早报时，读取当天每日复盘的“明天调整”，把计划与实际偏差、未完成关键任务和有效节奏反馈到明天的时间块；早报只写调整后的行动安排，不复制每日复盘全文。

## 历史耗时校准

- 每日生成计划前，通过任务完整索引读取今天、逾期和未来 7 天的事业任务，通过专注历史索引读取最近 30 天已完成的专注记录；同类样本不足 3 条时可继续分页扩展到最近 90 天，超过 90 天后可停止分页。
- 专注记录使用开始时间、结束时间和关联任务计算实际耗时；不依赖不可查询的公式字段。
- 明确的考试时长、面试起止时间和邮件完成窗口优先级最高；历史耗时用于估算准备、练习、复盘、简历和流程维护等开放任务。
- 同一任务有多个专注记录时，合并不重叠区间后求和。缺少时间、结束不晚于开始、跨日异常、明显重叠、0 分钟或超过 4 小时的单次记录标记为低可信，不直接进入普通任务估时。
- 同类任务优先采用清洗后样本的中位数，并向上取整到 15 分钟；样本较分散时使用较保守的上半区间，不用平均值被极端记录拉高。
- 区间清洗、同任务重叠合并、中位数/上四分位、15 分钟取整和置信度计算使用 `scripts/recruitment_rules.py estimate-focus`；模型只处理没有可用历史样本的低置信度默认值。
- 置信度：3 条以上干净同类记录为高；1–2 条为中；无同类记录或只有异常记录为低。低置信度估时使用任务明确时长或保守默认值，并在早报底部简要说明。
- 每日复盘后比较计划与实际专注：只有任务确实完成时才用实际耗时校准；未完成不能被当作“耗时更短”。连续出现 3 次以上同方向偏差后，再调整该类任务的默认估时。

## 按需查看完整秋招状态

用户明确询问“我现在的秋招状态”、整体盘点或阶段复盘时，再只读输出完整快照：

- 当前最重要
- 未来 7 天安排
- 流程风险
- AI 产品能力缺口
- 数据分析能力缺口
- 建议下一步

完整快照不默认复制进每日早报。能力缺口只引用能力图谱中有证据的节点，不从岗位名称猜测。
