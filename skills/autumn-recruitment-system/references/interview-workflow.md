# 真人面试、模拟与外部面经

## 五对象模型

每场真人面试恰好建立：

1. 真实面试页：面试复盘｜公司｜岗位｜轮次，场次类型=真实面试，初始场次状态=待准备、结果=待面试。
2. 模拟面试页：模拟面试｜公司｜岗位｜轮次，场次类型=模拟面试，并与真实页互相关联。
3. 日程：面试｜公司｜岗位｜轮次，任务类型=日程，排期为真实面试时间。
4. 模拟待办：模拟面试｜公司｜岗位｜轮次，排期仅为面试当天日期。
5. 复盘待办：面试复盘｜公司｜岗位｜轮次，排期仅为面试当天日期。

三条任务共同属性：状态=待办、领域=事业。真实面试页和模拟页的关联任务同时连接三条任务。

## 页面职责

- 真实面试页承载邀请信息、JD、外部面经、用户图片、面试前准备、现场事实和面试后复盘。
- 模拟页承载本轮模拟问题、追问、回答表现和模拟结论。
- 日程正文链接真实页；“下一步做什么？”开头放会议/签到/到场的首选可点击入口，并写面试时间、形式、平台或地点、会议号/访问码、预计时长、联系人、需携带材料和提前到场要求中邮件明确提供的内容。
- 模拟任务正文同时链接真实页和模拟页；“下一步做什么？”放真实页与模拟页的可点击链接，写针对性模拟动作、重点能力、预计时长及完成标准。若已有外部面经或 JD 入口，也附对应链接。
- 复盘任务正文链接真实页；“下一步做什么？”放真实页入口，并写恢复事实、录入原始问题、更新 Q&A 与能力图谱的完成标准；已有对应 Q&A、原始问题或能力节点页面时附可点击链接。
- 面试页正文保留来源邮件 ID 和发件人；不能从 Message-ID 猜发件人。
- 提醒或改期邮件提供新的会议链接、地点、访问码、联系人或材料要求时，同步更新原日程的“下一步做什么？”；不要只改页面正文。

## 去重、改期与取消

- 真实面试按邀请邮件 ID+发件人、岗位、轮次、面试时间精确去重。
- 模拟页按关联真实场次唯一；三条任务按关联场次/标题、类型、排期和来源证据去重。
- 改期同步更新两个页面和三条任务；日程保留时间，模拟与复盘只保留日期。
- 取消时两个场次标记取消、结果取消/放弃，三条任务设为放弃。
- 提醒邮件只补充时间、时长、会议号、地点、链接或发件人，不重复创建。

## 完成闭环

- 完成模拟：模拟任务=完成，模拟页场次状态=已复盘。
- 真实面试结束：真实页场次状态=已完成待复盘。
- 完成复盘：复盘任务=完成，真实页场次状态=已复盘。
- 复盘过程中更新原始问题、Q&A、经历素材、练习证据和能力图谱。

## 确定性校验

- 创建、改期、取消或完成联动前后，按 [脚本与数据契约](script-contracts.md) 组装 `plan.json`，运行 `scripts/recruitment_rules.py validate-plan`。
- 脚本检查每场真人面试的两个页面、一个日程、两个待办及日期一致性；错误未清零时不得提交邮件 UID。
- 脚本只检查结构和明确状态约束，不判断邮件是否语义上构成面试、改期、取消或终态。

## 每日模拟面试

- 每天只执行一次。今天有真人面试时，使用该真人面试的模拟页和模拟待办，作为当天针对性模拟。
- 真人面试自带模拟待办始终按真人面试日期维护，只在真人面试改期时同步改期；不得为了日常练习提前移动。
- 今天没有真人面试时，使用任务库中的 `每日模拟面试｜YYYY-MM-DD` 通用待办；未来 7 天有真人面试时，练习内容优先针对最近一场并可链接其模拟页。通用练习不创建新的面试库页面，完成内容进入能力练习库。
- 每次模拟实际问过的问题以“模拟面试”来源进入原始问题库；整场过程同时形成或更新一条能力练习记录，并按真实作答证据更新能力图谱。

## 外部面经

只在用户开始准备或执行模拟任务时实时搜索，不放入每日邮件自动化。

搜索顺序：

1. 同公司、同岗位、同轮次、近年。
2. 同公司、相近岗位或轮次。
3. 同岗位方向、其他公司。
4. 通用题型和公开岗位知识。

优先原始发布页、公司官方信息和高可信平台。标注来源、发布日期、公司/岗位/轮次和相关性层级；交叉归纳高频信号与单个候选人的偶发现象。只摘要，不大段复制，不宣称“本轮必考”。

搜索结果写入真实面试页“外部面经与来源”。外部问题默认不进入个人原始问题库；只有模拟中实际问过的问题，才以“模拟面试”来源进入。

## 用户图片

- 逐张读取题目、岗位、轮次、时间和上下文，并与网络结果去重。
- 标记“用户提供材料”，将结构化摘要写入真实面试页。
- 原图不自动上传 Notion；用户明确要求时再附档。
